# Публикация ChillZoneUnion на CurseForge

Материалы подготовлены для **0.6.2-beta**, WoW Forever **1.60.1**. Сам проект CurseForge и файл ещё нужно отправить через кабинет автора; окончательное решение принимает модерация.

## Что использовать

| Файл | Назначение |
| --- | --- |
| `project-fields.txt` | Название, короткое описание, категории, лицензия и ссылки |
| `description.md` | Готовое описание страницы: английский, затем русский |
| `changelog.md` | Изменения для поля Changelog загружаемого файла |
| `logo.png` | Логотип страницы, квадратный PNG не меньше 400 × 400 |
| `ChillZoneUnion-0.6.2-beta.zip` | Установочный архив, загружается как файл проекта |

Логотип и установочный ZIP прилагаются к набору для публикации. В исходниках ZIP создаётся командой `pwsh ./tools/package.ps1` и появляется в `build/`. Файлы страницы из этой папки в игру не устанавливаются.

## Порядок отправки

1. В кабинете автора CurseForge создайте проект для World of Warcraft с названием **ChillZoneUnion**.
2. Заполните Summary, категории и лицензию по `project-fields.txt`. Укажите Source и Issues в соответствующих отдельных полях.
3. Загрузите `logo.png`. Вставьте `description.md` в описание и проверьте предпросмотр: английский раздел должен быть первым. Скриншоты игрового окна можно добавить отдельно после проверки актуальной версии.
4. Оставьте Experimental выключенным. Отправьте проект на модерацию.
5. В разделе файлов загрузите именно `ChillZoneUnion-0.6.2-beta.zip`, укажите тип **Beta**, вариант **WoW Forever** и версию **1.60.1**. Вставьте текст из `changelog.md`.
6. Проверьте результат модерации и установку одобренного файла. Корректный путь после распаковки: `AddOns/ChillZoneUnion/ChillZoneUnion.toc`.

Если в списке нет WoW Forever или 1.60.1, не выбирайте похожую версию: уточните вариант у поддержки CurseForge. Порядок отдельных экранов кабинета может отличаться.

В описании проекта не нужна внешняя ссылка на прямое скачивание ZIP: файл устанавливается с CurseForge. Ссылки на исходники и сообщения об ошибках задаются отдельно.

## Почему пока Beta

Автоматические проверки и сборка не заменяют проверку двух настоящих игровых клиентов. Перед первым файлом типа Release проверьте:

1. Установку чистого архива, открытие `/cz` и `/чз`, состав, прокрутку, подсказки версий и статистику классов.
2. Подключение двух глав или офицеров по полным именам с явным подтверждением.
3. Сообщения в обе стороны через обычный гильдейский чат и `/czu`, без повторов и подмены автора.
4. Работу после выхода главы, смену доступного связного и восстановление после временного разрыва. Отдельно — работу уже настроенных клиентов при одних ветеранах онлайн и получение начальных настроек новой установкой от своего офицера.
5. Предложение перехода, согласие участника и ручное подтверждение выхода и приглашения.

**Проект только с Beta-файлами не появляется в приложении CurseForge.** Для приложения нужен хотя бы один файл типа Release, подходящий вариант игры и выключенный Experimental. Выпустите Release после успешной игровой проверки, сохранив Beta для текущей сборки.

## Состав архива и обновления

Установочный ZIP содержит 23 файла в одной верхней папке `ChillZoneUnion`, включая библиотеки и уведомления лицензий. `Tests`, инструменты сборки, служебные файлы GitHub и материалы страницы в него не включаются. Тесты остаются в репозитории и продолжают запускаться перед выпуском.

Версии 0.6.0, 0.6.1 и 0.6.2 используют прежние протокол и схему доверия; подключать гильдии заново после такого обновления не нужно. Для перехода с 0.5 и более ранних версий нужны обновление всех участников и новое подтверждение первого соединения.
